## Preserved application rules

Normalize U+0649 to U+06CC and ALEF followed by a quotation mark to ALEF/FATHATAN. Use the reshaper's `Arabic` table for Persian text, retain harakat and tatweel, keep mark shifting off, enable ZWJ, use shaped isolated forms, and retain default ligatures. Replace final HEH plus HAMZA ABOVE with U+FBA5 and apply the seven combined-diacritic substitutions before optional whole-input bidi ordering.

Both FATHATAN/SHADDA and KASRATAN/SHADDA map to U+FC5F, as in the reference handler. U+FC5E and U+FC5F have duplicate Maryam keys: their first values U+00DE and U+00DD win, respectively. Custom ligatures U+FC62 and U+FC63 have no Maryam entries and are therefore dropped in Compatibility mode. Multi-character mapping values remain intact because mapping occurs after ordering.

Compatibility mode normalizes Arabic digits to Persian digits, percent to U+066A, and Arabic comma to comma before mapping. The original loop preserves ASCII spaces, drops unmapped characters, adds an LF per input line, and strips edge LFs. The JavaScript equivalent preserves existing LFs and strips only edge LFs; it never applies general whitespace trimming. The VideoStudio option replaces U+0153 with U+00FE after mapping only.

## Fixture provenance

The `editor-corpus` section of `test/fixtures.js` preserves the contents of `src/#rnd/testCases.txt` as a JSON string, including its lack of a trailing newline. Its purpose is to exercise the whole original editor corpus without errors; it does not supply independent expected output.

## Library versions and runtime boundary

The plugin includes the ordinary classic JsBidi and JsParsiReshaper builds. The plain `test/conversion-test.js` test loads these local files directly. Libraries are downloaded and copied manually; there is no vendor manifest, hash enforcement, or update automation.

The reference application identifies older bidi and shaping versions. The new core preserves its application-specific rules while using the published JavaScript APIs and their documented limitations and fixes. It does not alter either independent library, implement clipboard access, normalize editor line endings, or provide editor-menu preprocessing.

Application mapping and JavaScript integration: LeoMoon Studios. Each conversion library's supplied documentation, license files, and source/modification notices accompany its unchanged vendored build. `THIRD_PARTY_NOTICES.md` identifies the JavaScript dependencies and their pinned source locations; Typr.js compatibility changes are documented there separately.

## SVG curve-export engine

Typr.js and OpenType.js were tested against the bundled `Vazirmatn[wght].ttf` and the reference checkout's `src/_fonts/LMN Maryam.ttf` using the final visual-order output from both conversion modes, including the Rial ligature. Both produced nonempty outlines with no missing glyphs. Typr.js was selected because the two required upstream source files total 96,942 bytes, compared with 528,484 bytes for the published OpenType.js 2.0.0 browser build, and required no runtime package or download. The test used Typr.js commit `02c121057750d8ab607873c1b369e717e858a643` and OpenType.js commit `5d65b6dcfab5115f90d375f8ba6b7942fdaa0138`; retained licensing and the small QML-runtime compatibility changes are recorded in `THIRD_PARTY_NOTICES.md`.

`SvgCurveExporter.js` consumes already converted visual-order text and the exact selected font bytes. It performs no shaping, bidi ordering, font fallback, or font lookup. Vazirmatn is the initial Unicode choice only; other Unicode designs and all Compatibility exports require the actual intended font file. Missing and non-outline glyphs are errors so the exporter never silently substitutes the UI font.
